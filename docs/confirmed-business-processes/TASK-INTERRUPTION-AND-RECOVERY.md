# 分级重试、任务中断与会话恢复完整业务流程

确认日期：2026-08-03  
实现状态：生产代码已接入全局、群聊、项目主 Agent及项目子 Agent执行链

## 业务目标

CCM将短对话和长任务分开处理。普通问答优先快速返回；开发、压缩和验收允许更长的有限重试。任何中断都先停止当前Provider请求、重试等待、工具、子Agent Runner及TestAgent，再根据可证明的现场决定自动恢复、等待用户恢复或永久取消。

```text
用户消息或开发任务
→ 选择模型重试档
→ 有限次数与总时间预算
→ 成功继续，或生成明确失败/中断回执
→ 终止当前执行进程并废止旧租约
→ 挂起并保留子Agent会话
→ 重新核验源码、权限、运行时和副作用
→ 安全自动恢复，或等待用户确认恢复
→ 同一任务、计划和会话创建新的执行attempt
```

## 分级模型重试

| 场景 | 最大尝试 | 总预算 | 失败后的处理 |
| --- | ---: | ---: | --- |
| 普通问答首轮 | 2次 | 60秒 | 明确失败并释放会话队首 |
| 计划与工具续跑 | 3次 | 120秒 | 停止当前Agent Loop，保留可重试状态 |
| 正式压缩、开发编排、TestAgent | 5次 | 360秒 | 中断当前任务并进入恢复判断 |
| 标题和非关键摘要 | 1次 | 30秒 | 使用受控降级，不阻塞主业务 |

单次请求超时遵循用户模型配置，但不能突破当前档位总预算。`400/401/403`、配置错误和权限错误只请求一次；`408/429/5xx`、网络断开和超时允许有限重试。`Retry-After`仅在剩余预算内生效。流式输出已经产生正文后不重放整轮，避免用户看到重复消息。

每次重试记录档位、当前次数、上限、剩余预算和脱敏失败原因。重试耗尽生成`CCM_MODEL_RETRY_EXHAUSTED`，长任务进入冷却和可恢复中断，不会无限循环请求。

## 停止与永久取消

### 停止当前执行

`interrupt`只停止当前执行轮。任务转为`blocked + recovery_required`，生成`TaskInterruptionReceiptV1`，同时保留：

- 原任务、计划、工作项和任务回放。
- 已完成的源码修改和工作区checksum。
- `task_agent_session_id`、`native_session_id`、消息和scratchpad。
- 工具授权快照、验收证据和最后checkpoint。

项目子Agent会话状态改为`suspended`，不会删除。旧执行租约和fencing token立即失效，迟到结果不能覆盖恢复后的新轮次。

### 永久取消任务

`cancel`是明确终态。任务变为`cancelled`，所有受管进程停止，子Agent会话关闭但历史仍保留。永久取消不会自动恢复，也不会自动回滚已经产生的源码修改；源码回滚必须走独立确认链。只有永久清理操作才能删除任务会话和执行证据。

## 中断回执

`TaskInterruptionReceiptV1`绑定精确任务、原因、执行attempt、checkpoint、工作区checksum、子Agent会话、原生CLI会话、副作用确定性、是否可恢复和是否允许自动恢复。公开页面不返回Prompt、API Key、CLI凭据或工具原始大结果。

以下原因可进入恢复判断：临时网络、Provider过载、Provider不可用、服务重启、租约失效和用户主动停止。无法分类的异常保持失败关闭，不能伪装成可安全恢复。

## 恢复门禁

服务端重新核验：

1. 中断回执checksum和任务身份有效。
2. 原进程已停止，旧租约不能再提交结果。
3. 工作区checksum、计划和checkpoint仍匹配。
4. 当前用户权限、工具授权和运行时仍有效。
5. 原生CLI会话身份可验证，或具备安全scratchpad降级条件。
6. 没有结果未知的Git提交、发布、部署或外部写入。

临时网络、Provider过载、服务重启和失效租约在全部证据成立时可自动恢复。用户主动停止、源码或权限变化、运行时变化、原生会话无法证明及副作用不确定时，页面显示“恢复任务”并等待用户确认。

恢复继续使用同一任务、计划、工作项、`task_agent_session_id`和可用的`native_session_id`，同时创建新的`execution_attempt`。执行内核会清除上轮的`finishedAt`、failure和cancellation状态，再记录新的attempt事件。原生resume不可用时使用持久scratchpad和任务快照续跑，但不重放已经完成的副作用。

## 三类主Agent

- 全局Agent：普通问答使用快速档；Mission和下游任务使用长任务档。等待用户的Run不占聊天队首。
- 群聊主Agent：首轮问答最多2次；工具续跑最多3次；项目子Agent开发和验收失败后生成任务中断回执。
- 项目主Agent：计划、开发、TestAgent和最终汇总共享同一Abort链。停止和永久取消是两个独立操作。
- 项目子Agent：收到中断后终止受管进程树并挂起原生会话；恢复时优先调用对应CLI的原生resume。

Web、飞书、工作台、群聊任务卡、项目任务卡和任务详情读取同一持久状态，不使用前端临时状态判断任务是否仍在运行。

## 恢复与回放

服务启动时分页扫描全部非终态任务。安全证据完整的任务重新进入原精确会话队列；需要用户确认的任务保持`recovery_required`，不会占用队首。任务回放展示中断原因、最后checkpoint、会话保留情况、恢复判断、新attempt和最终结果。

## 上线门禁

- 普通问候最多2次请求且60秒内结束。
- 长任务最多5次请求且总预算不超过360秒。
- 鉴权、权限和配置错误只请求一次。
- 用户停止不会被队列catch改写成永久取消。
- 中断不会删除子Agent会话或原生会话ID。
- 恢复创建新attempt，旧fencing token和迟到结果无效。
- 副作用不确定时绝不自动恢复。
- Provider Mock回归中付费调用为0。

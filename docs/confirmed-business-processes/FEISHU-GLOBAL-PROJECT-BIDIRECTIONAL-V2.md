# 飞书全局与项目 Agent 双向会话 V2

Date: 2026-07-29

Status: Confirmed and implemented

## 正式入口

飞书只允许进入两个主 Agent：

```text
飞书 -> 全局 Agent -> 群聊或项目任务链 -> 原全局飞书会话
飞书 -> 项目主 Agent -> 开发与验收链 -> 原项目飞书会话
```

群聊不建立飞书会话、不绑定飞书目标，也不能从飞书直接创建 `gcs_*` 会话。全局飞书任务可以把工作派发给群聊主 Agent，但群聊只是内部下游；计划、权限、TestAgent结果和终态沿原任务的 `FeishuOriginReceiptV2` 返回全局飞书会话。

## 入站与会话身份

WebSocket/ACP和HTTP事件回调先转换为 `FeishuInboundEnvelopeV2`，再进入同一处理链。身份绑定机器人应用指纹、`global_agent | project_agent`、精确项目、群聊、用户、话题根消息和平台消息ID。同群不同话题使用不同 `conversation_key_v2`；无话题消息进入该群的主会话。

全局入口拒绝项目和群聊目标，项目入口拒绝全局、群聊及项目ID不匹配。ACP必须由真实session映射证明目标，不能因为只有一个活动目标就自动选择。旧绑定能够证明作用域和话题时惰性兼容；旧群聊绑定只读保留，不再参与路由。

## 幂等、队列与恢复

应用指纹、目标、项目、精确会话和消息ID组成统一幂等键，因此同一消息经ACP和事件回调到达也只处理一次。持久回执状态为：

```text
received -> processing -> completed | failed
```

回执分别记录Agent处理阶段和脱敏结果，不保存Prompt、密钥或消息正文。失败回执可重新认领；不再使用处理前写入的进程内消息ID集合。

活动任务期间，模型判定为状态查询的消息立即回复；新要求进入当前精确会话队列。`FeishuQueuedTurnContextV2`保存原消息、话题、附件引用、目标与来源回执，执行时不会复用上一条消息的payload。服务重启后失效的`sending`租约恢复为待执行，同一会话串行，不同话题与不同项目相互独立。

项目飞书使用同一套持久`conversation-turn-control`。如果项目会话的源码开发或验收仍在后台执行，新消息不会返回409，也不会并发进入项目主Agent：服务端先以原平台消息ID幂等入队，向原话题返回队列位置，前一回合释放租约后再按FIFO领取。领取时若租约发生竞争，消息原样退回队首；普通问答的正式回复和新任务的接收/终态都通过该消息保存的项目飞书绑定投递。启动恢复器每3秒检查可执行队列，因此ACP重启、CCM重启或SSE断开不会丢失已经持久化的回合。

## 回复、权限与通知

业务回复只进入精确会话发件箱：普通回复关联原消息，话题回复关联原话题，任务阶段更新同一任务卡。临时失败最多重试五次；业务内容禁止降级到通用Webhook。通用Webhook仅用于用户主动配置的日报、周报和脱敏系统告警。

权限申请只有在任务带有全局飞书或项目飞书精确绑定时才发送飞书。网页任务和独立群聊任务不发送飞书；群聊处理全局飞书下游任务时继续使用全局来源回执。审批必须匹配来源会话、用户权限、签名、申请ID和待审批状态。

## 兼容与验证

- 全局与项目现有会话、任务、投递记录和历史消息不删除。
- Web全局、Web项目和Web群聊消息不会回传飞书。
- V2测试覆盖跨传输幂等、话题隔离、全局/项目隔离、群聊拒绝、排队原消息保真、项目FIFO与租约退回、项目精确ACP映射、启动恢复和禁止Webhook业务降级。
- Provider测试全部使用Mock，付费调用为0。

# 项目管理与运行

项目的仓库、Git变更、提交与远端协作详见[项目代码工作区与Git协作](./PROJECT-CODE-WORKSPACE.md)；持久终端和运行日志详见[终端与项目运行控制台](./TERMINAL-AND-RUNTIME-CONSOLE.md)。

## 项目主 Agent

每个项目会话都由项目主 Agent对用户负责。普通问答由项目主 Agent回复；开发任务由项目主 Agent制定计划并拆成当前项目内的工作项，再交给项目配置的唯一第三方开发 Agent。项目主 Agent不能选择兄弟项目，也不能读取群聊上下文。

开发 Agent完成执行不等于任务完成。涉及文件变更或验证的任务必须经过 TestAgent独立验收；失败时回到同一开发 Agent会话返工，最多三轮。只有 TestAgent证据门禁和项目主 Agent最终复盘都通过后，正式任务才进入完成状态。

项目会话正文只保存用户和项目主 Agent的正式消息；开发输出、TestAgent报告和返工过程保存在任务时间线与任务回放。项目独立维护测试目标，不依赖加入群聊。

## Web 与飞书会话

项目会话按来源分为 Web 会话和飞书会话。来源由当前项目 cc-connect 文件中的真实 `active_session/user_sessions` 映射和会话 `source` 字段确定，不根据会话名称或消息文字猜测。

项目页面可以新建飞书会话，并将当前项目已发现的飞书群聊、私聊或话题目标绑定到该精确会话。飞书目标的新消息随后进入项目主 Agent；列表显示当前绑定名称。Web 会话不能绑定飞书目标，项目之间不能读取或复用目标，全局助手绑定不参与项目绑定；群聊不再拥有飞书绑定。

网页项目会话产生的普通回复不会自动发送到飞书。删除飞书会话时会同步清理该项目 cc-connect 的活动与历史会话映射。

Windows 上的项目飞书长连接和它启动的 Claude Code、Codex、Cursor、Gemini CLI 或 OpenCode 任务都必须在无控制台进程树中执行。项目消息不能弹出命令行窗口；Agent 设置页中由用户主动点击的登录、授权或退出流程仍可打开必要的浏览器或交互窗口。

项目飞书机器人只负责收发平台消息。运行时 Agent 必须使用项目ACP将消息交给CCM，并按应用、项目、`chat_id + open_id`和话题根消息解析精确绑定；无法证明ACP映射时拒绝路由，不能因只有一个目标而自动选择。普通问答由项目主 Agent回复；开发任务才进入规划、第三方开发 Agent和TestAgent闭环。

## 项目身份

每个项目有两个名称：

- 内部项目 ID：创建后保持稳定，用于配置文件、会话、记忆、任务、群聊成员、日志索引和飞书凭据绑定。
- 项目显示名称：用户可以在编辑项目中修改，用于项目列表和页面展示。

修改显示名称不会迁移源码目录，也不会创建第二份项目数据。旧项目没有显示名称时直接显示内部 ID。

## 两类启动

`连接 Agent` 只连接项目 Agent、cc-connect 会话和项目通知通道，不运行源码。

`启动项目` 执行选中的源码运行配置。每个模块可以独立启动、暂停、重新运行和构建，同一项目允许前端、后端与多个服务同时运行。

暂停的含义是结束精确进程树并保留运行配置，不是冻结进程内存。重新运行会创建新进程。

## 配置来源

运行配置只来自真实项目配置文件或用户手动输入。系统可以识别 Node、Maven、Gradle、Go、Rust 和 .NET；无法可靠判断的项目不会生成猜测命令，也不会自动安装依赖。

Spring Boot 模块结合构建插件、`mainClass` 和源码中的 `@SpringBootApplication` 识别。父聚合 POM 只提供构建，真实启动模块提供独立启动配置；没有用户默认项时优先选择可启动模块。Windows Java 项目通过受控 Shell 调用 Maven/Gradle，并只继承必要的 Java 构建工具链环境。

运行和构建日志通过精确项目与配置绑定的 SSE 流进入 IDEA 风格控制台，支持 ANSI 颜色、跟随、暂停、搜索、复制、停止和重新运行。多模块 Maven 启动遇到可证明的本地 SNAPSHOT/BOM 缺失时，可以先准备 reactor；被根 POM 排除但仍被目标模块依赖的本地源码模块按 BOM/POM 优先顺序安装后重试。恢复只用于启动前依赖准备，不修改项目 POM，也不绕过正式打包测试。

用户修改自动识别配置后，重新扫描不会覆盖修改。全局 Agent 或飞书在多个配置且没有默认项时必须询问用户，不能随机选择。

## 安全边界

- 源码运行 PID 与 Agent 连接 PID 完全隔离。
- 命令只能在项目目录内执行，禁止 shell 拼接、命令替换和目录越界。
- CCM 重启后无法验证归属的 PID 不允许自动终止。
- CCM 正常停止或重启会先通过本机清理事务停止自己管理的源码进程并提交停止状态；只有异常崩溃或清理不可达时才按无法验证 PID 处理。
- 页面直接点击是对精确配置的明确操作；全局 Agent 和飞书发起运行仍需高风险确认。
- 项目归档前必须停止 Agent、源码进程和构建任务。
- 项目主 Agent任务、开发 Agent会话、TestAgent工单和权限申请必须绑定精确项目会话，兄弟会话互不复用。

# 音乐意图与统一播放业务流程

曲库、统一搜索、下载、歌单、历史、歌词、播放设置和重复治理见[音乐媒体库与播放平台](./MUSIC-LIBRARY-AND-MEDIA.md)。

## 模块关系

全局网页、全局飞书和音乐助手都可以发起点歌，但只生成一个权威播放决定，并交给同一个浏览器音频引擎。音乐助手没有多会话列表；它使用单例连续性和音乐偏好记忆。

## 文本请求流程

1. 用户文字进入统一语义运行时，生成 `none | search | play | convert` 结构化决定。
2. 服务端按决定搜索本地、网易、B站或抖音候选；`auto`模式并行读取四个来源。
3. 精确唯一候选通过身份校验直接使用；多个候选需要选择时，模型从候选列表返回选中索引。
4. 助手回复、结果列表和播放器命令引用同一个 `MusicPlaybackDecisionV2`，不能推荐A却播放B。
5. 新播放指令原子地把旧非终态指令标记为 `superseded`，只有最新generation可以播放。
6. 浏览器音频引擎先peek并准备资源，准备完成后才claim，播放后提交真实终态回执。

## 模型边界

- 具体歌曲、仅歌手、情绪、场景、曲风和随机请求都由模型理解，不使用关键词、正则或随机规则代替语义判断。
- 模型不可用、超时或返回无效结构时，文本点歌失败关闭，不产生播放副作用。
- 用户直接点击歌曲、播放/暂停、上一首/下一首和队列控制属于显式操作，不需要模型。
- AI推荐关闭时，情绪和场景请求只提示用户；自动选歌关闭时返回候选等待点击。

## 队列与失败恢复

播放命令状态为：

`pending → resolving → ready → claimed → playing → completed | failed | superseded | cancelled`

- claim租约15秒，播放器每5秒续租；页面关闭或心跳丢失后命令可以重新领取。
- 旧下载即使后来完成，也不能越过最新generation自动播放。
- 音频临时错误最多重试三次，随后标记原因并跳到下一首。
- 浏览器自动播放被拦截时进入等待用户手势，不把它当作歌曲失败。

## 来源隔离

- Web请求只更新原Web会话，飞书请求只回原飞书会话。
- 初始回复只能说明“已接收，正在选歌”；真实开始播放后才能显示“正在播放”。
- 搜索、下载、播放、失败或被替代都更新同一稳定回复消息，避免重复Agent气泡。

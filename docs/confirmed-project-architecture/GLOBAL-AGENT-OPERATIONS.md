# 全局 Agent 运行体系

## 定位

全局 Agent 是跨项目入口，负责普通问答、系统查询、需求语义判断、任务目标选择、下游派发和最终汇总。它不替代群聊主 Agent或项目主 Agent直接开发源码。

## 会话与入口

- Web 会话和飞书会话使用不同的精确会话身份，互不转发回复。
- 新会话在用户发送第一条消息后才持久化。
- 每个会话维护 canonical transcript、隐藏工具执行链、压缩边界和长期记忆召回。
- 普通问答直接回复；开发需求才创建 Global Mission 或统一任务。

## 运行流程

1. 接收文字、附件和在线文档，绑定精确来源会话。
2. 通过统一语义运行时判断问答、工具操作或开发任务。
3. 问答读取全局授权的 Skill/MCP、知识和记忆；工具调用写入隐藏执行账本。
4. 开发需求选择群聊或项目目标，创建下游任务并持续监督。
5. 计划、权限、TestAgent结果和终态沿 origin receipt 回到原 Web 或飞书会话。
6. 只有结构化终态和正式回复进入用户可见会话，子 Agent原始输出进入任务回放。

## 控制与恢复

- Web、兼容聊天接口和飞书入站统一进入服务端权威会话队列；同一精确会话严格串行，Mission监督不长期占用聊天队首。
- Global Run 支持确认、暂停、恢复、取消和用户补充要求，自然语言续跑由模型判断，不使用关键词或正则。
- 普通写操作必须持有绑定用户、来源、会话、消息、目标和工具范围的单轮授权回执；高风险操作始终等待用户确认。
- 服务重启后扫描全部非终态Run和未投递终态；未证明归属的旧租约、上下文或授权不会直接继续执行。
- Provider暂时失败走统一重试和任务级熔断；模型决策失败时不使用关键词兜底。
- 超大上下文按完整轮次分段执行正式模型压缩，任一分段失败都不会推进压缩边界或丢弃旧消息。
- Run终态先持久化，再由发件箱向Web、飞书、回放和长期记忆分别投递；投递失败不改变业务终态。
- 全局工具权限、后台操作、运行时钩子和质量中心都有独立审计接口。完整流程见[全局Agent运行体系V2](../confirmed-business-processes/GLOBAL-AGENT-RUNTIME-PRODUCTION-V2.md)。

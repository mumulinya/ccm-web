# 飞书全局与项目 Agent 双向会话

Date: 2026-07-29

Status: Confirmed

## 会话模型

每个飞书来源会话映射到一个独立的全局 Agent 会话。身份包含应用、群聊、用户和话题根消息；同群不同话题不会共享历史、队列或回复目标。飞书用户消息、全局 Agent 回复、运行状态与任务结果写入该精确会话；项目飞书、其他飞书话题和 Web 全局会话不会被混入。

飞书只直接连接全局 Agent和项目主 Agent。群聊不拥有飞书会话或飞书绑定；全局飞书任务分派给群聊后，群聊结果沿原全局飞书来源回执返回。

全局助手页面按“网页会话”和“飞书会话”分组展示。飞书目标可以绑定到一个精确的飞书会话，列表会标记当前绑定目标；用户也可以在 Web 页面新建飞书会话后再绑定。Web 会话不能绑定飞书目标，“清空网页会话”不会删除飞书会话。

## 入站流程

1. WebSocket/ACP和事件回调统一生成V2入站信封，校验应用、目标、项目、发送者、话题和消息ID。
2. 根据应用、`chat_id + open_id + thread/root`查找精确绑定；ACP映射无法证明时失败关闭，不使用单目标兜底。
3. 文字直接进入 Agentic Loop；图片和附件先下载、保存并走需求来源解析。
4. 全局 Agent 可以回答问题、查询系统、管理任务，或者把业务开发任务交给群聊主 Agent、项目 Agent 和 TestAgent 链路。
5. 新建的 run、mission 和 task 都追加到原飞书会话绑定。
6. 开发请求没有明确目标时，全局 Agent返回可投放项目/群聊的签名交互按钮和编号列表；用户点击、回复编号或完整名称后，服务端校验目标仍可用，并在原`waiting_clarification` run上继续。

飞书目标选择只确定群聊或项目，不选择下游精确会话。任务落地时按`global_agent`来源解析目标的自动化会话绑定；不存在绑定则自动创建。网页全局 Agent使用同一规则，但允许每条消息多选目标。

## 出站流程

普通回复优先回复原 `message_id`；话题消息回到原线程。计划、执行、TestAgent、返工和完成阶段更新同一张任务卡。如果发送临时失败，消息进入持久outbox，最多重试五次。业务正文不能回退到通用Webhook；耗尽后只发送脱敏系统告警，并可在设置页精确手动重试。

## 权限流程

全局 Agent 下发的开发任务如果触发项目子 Agent 权限申请：

1. 权限申请记录 `originType=global` 和来源全局会话 ID。
2. 飞书通知包含项目、操作、风险、理由和申请 ID。
3. 用户可点击签名卡片的“批准一次”或“拒绝”；全局来源继续兼容文字命令。
4. 后端校验用户管理员角色、卡片签名、过期时间、原消息 binding、申请归属和 `awaiting_user` 状态。
5. 批准后创建绑定任务、项目、子 Agent、Provider native session 和 checksum 的单次限时租约，并恢复原任务。
6. 兄弟飞书会话不能查询、批准或消费该权限。

任务派发中心和对应 Web 全局会话仍同步显示同一条权限申请，任何入口处理后其他入口都会刷新为已处理。

项目飞书来源使用同一套交互卡片审批。独立群聊来源不发送飞书；全局飞书下发到群聊的任务继续使用原全局来源绑定。

## 用户角色

- 查看者只能问答、只读分析和查看状态。
- 操作员可以创建、排队、调整和停止任务。
- 管理员额外拥有权限审批能力。
- 设置页可选择允许所有已识别用户，或只允许明确映射的名单用户。

## 运行中消息

- `引导：内容`：在安全节点调整当前全局 Agent 运行。
- `排队：内容` 或普通新消息：当前任务结束后自动处理。
- `停止`：停止当前工作，保留已排队消息。
- 相同飞书消息经ACP和事件回调重复到达也不会重复执行。

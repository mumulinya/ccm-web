# 飞书全局 Agent 双向会话

Date: 2026-07-22

Status: Confirmed

## 会话模型

每个飞书来源会话映射到一个独立的全局 Agent 会话。飞书用户消息、全局 Agent 回复、运行状态与任务结果写入该精确会话；其他飞书群、其他用户会话和 Web 全局会话不会被混入。

全局助手页面按“网页会话”和“飞书会话”分组展示。飞书目标可以绑定到一个精确的飞书会话，列表会标记当前绑定目标；用户也可以在 Web 页面新建飞书会话后再绑定。Web 会话不能绑定飞书目标，“清空网页会话”不会删除飞书会话。

## 入站流程

1. 飞书事件回调校验 Verification Token、事件类型、发送者和消息幂等 ID。
2. 根据 `chat_id + open_id` 查找飞书目标绑定；有 `active_session_id` 时使用绑定的精确飞书会话，否则解析或创建独立会话。
3. 文字直接进入 Agentic Loop；图片和附件先下载、保存并走需求来源解析。
4. 全局 Agent 可以回答问题、查询系统、管理任务，或者把业务开发任务交给群聊主 Agent、项目 Agent 和 TestAgent 链路。
5. 新建的 run、mission 和 task 都追加到原飞书会话绑定。

## 出站流程

普通回复优先回复原 `message_id`；话题消息回到原线程。计划、执行、TestAgent、返工和完成阶段更新同一张任务卡。没有原消息 ID 的兼容绑定才向原 `chat_id/open_id` 新发消息。如果发送临时失败，消息进入持久 outbox，最多重试五次；耗尽后通知 Web 与桌面宠物，并可在设置页精确手动重试。

## 权限流程

全局 Agent 下发的开发任务如果触发项目子 Agent 权限申请：

1. 权限申请记录 `originType=global` 和来源全局会话 ID。
2. 飞书通知包含项目、操作、风险、理由和申请 ID。
3. 用户可点击签名卡片的“批准一次”或“拒绝”；全局来源继续兼容文字命令。
4. 后端校验用户管理员角色、卡片签名、过期时间、原消息 binding、申请归属和 `awaiting_user` 状态。
5. 批准后创建绑定任务、项目、子 Agent、Provider native session 和 checksum 的单次限时租约，并恢复原任务。
6. 兄弟飞书会话不能查询、批准或消费该权限。

任务派发中心和对应 Web 全局会话仍同步显示同一条权限申请，任何入口处理后其他入口都会刷新为已处理。

群聊和项目来源如果保留有效飞书任务绑定，也使用同一套交互卡片审批，不再要求必须回到 Web 页面。

## 用户角色

- 查看者只能问答、只读分析和查看状态。
- 操作员可以创建、排队、调整和停止任务。
- 管理员额外拥有权限审批能力。
- 设置页可选择允许所有已识别用户，或只允许明确映射的名单用户。

## 运行中消息

- `引导：内容`：在安全节点调整当前全局 Agent 运行。
- `排队：内容` 或普通新消息：当前任务结束后自动处理。
- `停止`：停止当前工作，保留已排队消息。
- 相同飞书消息 ID 不会重复执行。

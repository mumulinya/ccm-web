# 自动开发业务流程

CCM 的自动开发不是单独页面里的另一套任务系统。任务派发、工作台、全局 Agent、群聊会话和项目会话最终都写入同一持久任务系统，并由同一队列、权限、TestAgent和任务回放处理。

## 入口规则

- 普通询问由当前主 Agent直接回答，不创建任务。
- 开发、文件修改、复杂验证和业务文档需求由统一大模型判断并形成执行计划。
- 一个需求可以成为一个任务，也可以成为包含多个子任务和依赖关系的 Epic。
- 用户上传的图片、PDF、Office 文件和文本资料会进入需求摄取记录与任务来源。

## 执行规则

- 同一精确群聊或项目会话按顺序执行任务。
- 不同会话可以并行。
- 高优先级任务可以插到等待队列前部，但不能绕过依赖、权限和验收。
- 群聊任务由群聊主 Agent协调多个项目成员；项目任务由项目主 Agent协调当前项目唯一开发 Agent。
- 代码或文件变更必须通过 TestAgent；失败自动返工并复验，最多三轮。

## 回放规则

任务派发与任务回放通过同一 task ID、parent task ID 和 trace ID 绑定。任务回放展示需求、计划、分派、开发、变更、测试、返工、验收和最终结果，不只展示一段 Agent 输出。

详细实现见 [全入口自动开发与会话队列](../main-agent-workchain/automatic-development/unified-multi-entry-auto-development-2026-07-24/README.md)。

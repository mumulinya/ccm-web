# 项目 TestAgent 登录态验收

## 目标

需要登录的 Web、H5 和管理端项目，通过项目页面的“测试目标”配置登录入口与认证方式。配置属于精确项目，不与其他项目共享；项目会话和包含该项目的群聊会话共同读取这一份配置。

## 配置流程

1. 在项目管理页面打开“测试目标”，新建或编辑目标。
2. 填写目标访问地址，例如 `http://127.0.0.1:5173`。
3. 认证方式选择“账号凭据”时，配置登录路径、页面字段、提交按钮以及登录成功文本或 URL 特征。
4. 用户名、密码和其他认证字段写入本地加密凭据仓库，接口和浏览器页面只返回是否已配置。
5. 也可选择项目目录内的 Playwright Storage State，或选择已有浏览器会话 Provider。

项目“测试目标”页面是登录资料的唯一配置入口，但用户名和密码底层仍按项目只保存一份。群聊“测试目标”只负责声明某个入口是否需要认证；选择“使用项目账号密码”后，运行时从目标所属项目读取登录资料。

登录路径是前端页面路由，例如 `/login`。TestAgent 会将它与访问地址组合成完整登录地址，不是后端登录 API 地址。

## 执行链

```text
项目测试目标
-> 读取所属项目的唯一登录配置
-> 解密当前目标所需凭据到临时环境变量
-> 生成确定性浏览器登录步骤
-> 打开登录路径
-> 按配置标签填写字段
-> 点击配置的登录按钮
-> 验证成功文本或 URL
-> 执行业务验收与浏览器检查
-> TestAgent 门禁
```

密码不会写入 TestAgent handoff、任务回放、日志或模型正文。浏览器动作只保存环境变量名称，真实值只存在于该次 TestAgent 子进程环境。

## 失败策略

- 缺少凭据、登录字段或成功条件时拒绝保存账号登录配置。
- 登录失败时 TestAgent 不得跳过受保护页面并宣称通过。
- Storage State 必须位于项目目录内，目录越界时拒绝执行。
- 已有会话 Provider 不可用时明确阻塞，不伪造登录态。
- 登录验证失败进入项目主 Agent 返工与复验，最多三轮。
- 项目登录配置变化会改变目标 checksum，已生成但未执行的旧验收计划必须重新生成。

## 验证

- 项目主 Agent 编排自测验证账号凭据会生成登录页访问、字段填写、按钮点击和成功 URL 断言。
- 验证 Storage State 路径进入正式浏览器工作单。
- TypeScript 检查、生产构建和项目任务回归均不调用付费 Provider。

# 模型语义路由独立自检

## 结论

本次不是重复执行原静态测试，而是从全局、群聊、项目、需求、TestAgent、记忆和音乐生产入口重新追踪模型决策。自检发现并修复了会让本地规则重新接管语义，或让模型字段在后续轮次丢失的问题。

## 已修复问题

- 群聊显式任务不再手工构造残缺 `workflowDecision`；显式操作只固定执行模式，Skill、代码变更、验证、复核、风险和记忆策略仍由模型决定。
- 群聊协调模型的第二轮结果与统一预检决定按字段合并，模型未返回的字段不再被重置为空。
- 群聊需求分解的生产入口改用 `decomposeRequirementWithModelCoordinator`；旧名称只保留扩展兼容别名。
- 需求预览在模型提取失败时返回 `503`，不再根据用户原文和本地默认项创建任务；影响范围来自模型结构化需求。
- 全局 Agent 每轮模型决定继承上一轮未覆盖字段，避免 Skill、代码变更、验证和记忆策略在循环中丢失。
- 全局澄清中的授权撤销由模型输出 `authorizationDirective`；真正授予写权限仍必须经过服务端明确授权，模型不能自行授权。
- 记忆是否忽略由模型输出 `memoryPolicy`，不再扫描“忽略/不要使用记忆”等自然语言。
- 返工方向、独立验证、复验和新 worker 选择只接受结构化标志；独立复核结论只读取结构化 verdict/status，未知文本 fail closed。
- 歌手候选只按 `artist/author/singer` 字段过滤，歌曲标题包含歌手名不再被误认为该歌手作品。

## 确定性边界

仍保留正则或字符串匹配的部分不负责理解用户意图：命令与斜杠语法、ID、URL、路径、文件类型、Provider 错误、prompt-too-long、MCP/回执协议字段、安全策略和结构化状态枚举。它们负责验证模型结果和保护执行边界，不选择工作流、Agent、Skill 或动作。

权限门禁保持独立：模型可以报告风险、确认建议和授权语义变化，但不能绕过用户/主 Agent 审批、工具 allowlist 或服务端风险规则。

## 回归门禁

`scripts/model-semantic-routing-audit.mjs` 扩展为 21 项，覆盖：

- 显式任务仍经过模型语义补全。
- 群聊和全局多轮字段连续性。
- 需求预览 fail closed。
- 结构化记忆策略、授权指令、返工路由和复核状态。
- 歌手字段过滤、模型选曲和无本地随机兜底。
- TestAgent 结构化检查与规划失败门禁。

验证全部使用本地 mock 或静态/确定性测试，付费 Provider 调用为 `0`。

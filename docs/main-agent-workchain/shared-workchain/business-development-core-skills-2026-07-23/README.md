# 业务开发核心 Skill

## 目标

CCM 内置三项面向业务开发的工作流 Skill，把“理解业务、约定数据、验证业务”接入真实 Agent 工作单，而不是只作为设置页中的可选说明。

| Skill | 作用 | 主要执行者 |
| --- | --- | --- |
| `ccm-business-rule-modeling` | 明确角色、权限、状态流转、不变量、异常和恢复规则 | 群聊主 Agent；独立项目 Agent |
| `ccm-interface-data-contract` | 明确 API、事件、字段、存储、迁移、错误和兼容契约 | 群聊主 Agent；项目 Agent/项目子 Agent |
| `ccm-business-scenario-acceptance` | 按正常、拒绝、边界、重复、重试、持久化和恢复场景验收 | 项目 Agent/项目子 Agent；TestAgent；群聊主 Agent 复核 |

三项均属于 CCM 随包发布的不可修改内置 Skill。服务启动时由内置目录校验并注册，不复制为第二套用户 Skill。

## 业务流程

### 群聊业务开发

1. 群聊主 Agent 判断用户消息是否为真实工作请求。
2. 业务任务涉及角色、权限、状态或生命周期时加载业务规则建模。
3. 涉及接口、字段、数据库、事件、迁移或兼容时同时加载接口与数据契约。
4. 主 Agent 基于确认规则拆解工作单并派发项目子 Agent。
5. 项目子 Agent同步契约 Skill，并在业务任务中加载场景验收进行交付前自验。
6. 群聊主 Agent复核业务场景、回执和证据；TestAgent 独立复验关键场景。

### 独立项目会话

1. 项目会话先通过统一模型判断是普通问答还是开发任务。
2. 普通问答不注入业务开发 Skill。
3. 开发任务没有群聊规划层，因此项目 Agent按内容动态选择规则建模、数据契约和业务场景验收。
4. 选中的 Skill 合并进项目已有 MCP/Skill 授权，写入第三方 Agent 的隔离工具快照和执行提示。
5. Claude Code、Codex、Cursor、Gemini CLI 和 OpenCode 只收到当前任务选中的 Skill；完成后须在交付回执中报告实际使用情况。

### 全局 Agent

全局 Agent负责识别目标项目和群聊、形成跨项目任务并监督结果，不加载项目级业务 Skill。详细规则由绑定群聊主 Agent或独立项目 Agent处理，避免重复上下文和职责混乱。

## 选择边界

- 业务规则触发：业务流程、角色权限、状态流转、审批、订单、支付、退款、库存、订阅等。
- 数据契约触发：前后端联调、API、字段、DTO、数据库、事件、MCP、迁移、分页、错误码和兼容等。
- 业务验收触发：业务功能需要验证权限、状态、重复提交、重试、失败恢复或持久化。
- 纯颜色、字体、间距、背景、圆角和布局修改不加载这三项，继续使用视觉 QA Skill。
- “错误码”属于契约，不再误判为运行故障；只有报错、失败、超时、异常或明确状态码等证据才加载故障诊断。
- 群聊主 Agent和项目 Agent每轮最多加载 6 项匹配 Skill，角色提示总预算限制为 12,000 字符。

## 失败与安全

- Skill 不授予执行权限；高风险命令继续经过 CCM 权限代理。
- 来源不足时必须标记假设或阻塞，不得编造业务政策、字段或验收通过结果。
- 构建成功不能替代业务验收；缺少环境、凭据或测试数据时结论为 `blocked`，不能虚报 `pass`。
- 选中的内置 Skill 未同步到第三方 Runtime 时，现有工具派发门禁阻止任务启动。

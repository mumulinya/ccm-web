# 代码变更目录树与模块分组

日期：2026-07-23

## 目标

将代码协作页的变更文件列表升级为接近 IDEA 的目录定位体验，让用户先看出哪些目录或模块发生变化，再进入具体文件查看 Diff。

## 分组模式

- **目录**：默认模式，按 Git 相对路径构建完整目录树。
- **模块**：按路径第一级目录聚合，例如 `frontend`、`backend`、`docs`；根目录文件单独归入“项目根目录”。
- **状态**：保留原有冲突、同时暂存和修改、已暂存、工作区、未跟踪分类。

分组选择保存在浏览器本地，用户下次进入代码协作页时继续使用上次模式。

## 目录树交互

- 目录显示其全部后代变更文件数量。
- 支持逐级展开和收起。
- 搜索文件或目录时自动展开匹配路径。
- 目录复选框可以选择或取消选择该目录下全部变更文件。
- 部分文件被选择时，父目录显示半选状态。
- 每个文件继续展示 Git 状态、增删行数、冲突提示并可打开对应 Diff。
- 目录树只使用 `/api/git/status` 已返回的真实变更路径，不扫描磁盘，也不展示无关文件。

## 与 Git 流程的关系

目录级选择最终仍转换为明确的文件路径列表，提交预检和后端 `git commit --only` 安全边界没有变化。选择目录不会隐式提交该目录中未出现在 Git 变更列表里的文件。

# 文档驱动需求集合与自动执行

## 目标

业务需求池支持用户提交一段业务描述、一张或多张图片，或 PRD、接口说明等文档。系统先让主模型理解完整资料，再生成可核验的任务图；用户确认后才创建正式任务并进入现有自动开发队列。

它不是另一套任务数据库。需求集合、执行任务、TestAgent 验收与任务回放仍使用现有持久任务、时间线、证据和队列。

## 用户流程

```text
上传资料或描述
-> 模型读取并整理业务目标
-> 模型拆分可执行任务和验收标准
-> 用户检查、编辑、合并、删除、排序和调整依赖
-> 服务端重新校验任务图
-> 原子创建需求集合父任务和全部子任务
-> 无前置依赖的任务进入对应会话串行队列
-> 前置任务通过交付验收后解锁后继任务
-> 代码或文件改动经过 TestAgent 独立验收
-> 需求集合在任务回放中形成一条完整任务链
```

## 需求池中的两类数据

### 文档需求集合

- 来自“上传资料并智能拆分”。
- 一份需求可以形成多个项目或群聊任务。
- 每个任务保存业务目标、执行范围、执行位置、验收标准、前置依赖和来源证据。
- 集合卡只显示整体进度、任务数量、异常数量、资料数量和执行目标。
- 点击集合卡进入权威任务回放，查看父任务、子任务、TestAgent、返工和最终交付。

### 传统需求卡

- 来自群聊共享文档导入等旧入口。
- 一份资料形成一张待开发卡，可补充、阻塞或批量派发。
- 保持兼容，不会被自动迁移或删除。

## 编辑与确认

模型拆分完成后，用户可以：

- 修改任务标题、业务目标、工作范围与验收标准。
- 把任务指定到明确群聊或项目，也可以保留由主 Agent 按能力选择。
- 上移、下移、新增、删除或合并任务。
- 选择其他任务作为前置依赖。

系统生成的跨任务集成验收是最终交付门禁，可调整目标、范围和验收标准，但不能删除或与开发任务合并。其他业务任务仍可自由删除和合并。

浏览器先检查空标题、空目标、重复标识、未知依赖、自依赖和循环依赖。确认接口再次使用权威校验器检查完整 DAG；校验失败时不创建任务、不进入队列。

## 队列与验收

- 确认接口原子创建 `requirement_epic` 父任务及其子任务，避免只创建一半。
- 同一精确会话继续使用现有串行队列；优先级只改变候选顺序，不绕过前置依赖。
- 只有没有前置依赖的根任务会立即入队。
- 前置任务必须通过正式交付门禁，后继任务才会解锁。
- 子 Agent 进程退出成功不等于任务完成；存在代码或文件变化时仍需 TestAgent 和主 Agent 验收。
- 失败、阻塞与返工保留在同一任务链，不会重复创建新的无关联需求。

## 任务回放

任务回放以需求集合父任务为根，自动聚合：

- 用户目标与原始资料来源。
- 模型规划和经用户确认的任务图。
- 每个项目或群聊子任务的执行进度。
- 开发 Agent 结果、TestAgent 独立验收和返工记录。
- 真实变更文件、验证命令、截图和交付证据。
- Provider 重试、模型调用和已记录 Token；缺失数据不会估算。

需求池不复制这些明细，只提供集合状态和入口，避免重复事实源。

## 安全与失败策略

- 语义拆分只使用配置的主模型，不使用关键词或正则替代。
- 模型不可用、资料不可读或任务图无效时 fail closed，停留在确认前。
- 来源证据随任务保存，任务拆分结果不能脱离原始资料。
- 服务端确认使用客户端提交的编辑结果并再次标准化，客户端校验不能绕过服务端门禁。
- 内容哈希和幂等键用于防止同一确认请求重复建单。
- 已确认需求的后续版本使用原有版本差异流程，只重开受影响任务。

## 接口

- `POST /api/usability/intake/preview`：读取资料并生成待确认任务图。
- `POST /api/usability/intake/confirm`：校验编辑后的任务图，原子建单并派发根任务。
- `GET /api/tasks/daily-dev-backlog`：返回传统需求卡、文档需求集合及状态统计。
- `GET /api/tasks/replay?task_id=<epic_id>`：读取需求集合的完整任务链。
- `GET /api/tasks/requirement-epic/self-test`：运行不调用 Provider 的任务图、原子持久化、依赖解锁和验收门禁自测。

## 验证

- TypeScript：`npm run check`
- 前端生产构建：`npm run build:frontend`
- 后端生产构建：`npm run build:backend`
- Requirement Epic 自测：直接执行编译后的 `runRequirementEpicSelfTest`
- 文档链接：`npm run docs:check`

测试不调用付费 Provider。真实模型拆分由用户在已配置 Provider 的正常业务请求中触发。

# 开发 Agent 可见登录流程修复

> 历史记录：该终端登录方案已被 `../development-agent-browser-auth-2026-07-23/README.md` 的统一浏览器认证会话替代，不再代表当前产品行为。

## 问题

Windows 页面点击开发 Agent 的“登录”后，旧实现只创建一个分离的 PowerShell 子进程并立即返回成功。CCM 无法证明窗口实际可见；当后台进程、系统策略或窗口创建方式阻止显示时，页面仍错误提示“已打开登录窗口”。

## 修复

- Windows 通过隐藏的启动器调用 `Start-Process`，显式创建独立、可见且保持打开的认证终端。
- 页面不再宣称窗口必然打开，改为“已尝试打开”，与可证明事实一致。
- 后端在 Windows 和服务器环境都返回安全、固定的认证命令。
- 页面始终显示兜底命令并提供复制按钮；Windows 提示在本机终端运行，Linux/macOS 提示在 CCM 服务器 SSH 中运行。
- 认证完成后点击“重新检查”，只有 CLI 正向证据才会切换为“已登录”。

## 验证

- Cursor 否定认证文本不会误判。
- Windows 可见终端启动器、服务器手动命令和页面兜底入口均纳入静态回归。
- 页面构建、认证设置测试和发布回归不调用付费 Provider。

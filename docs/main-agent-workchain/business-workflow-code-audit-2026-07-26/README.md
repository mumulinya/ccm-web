# 业务开发工作链代码审查收口

## 审查结论

本轮完成了全局 Agent 到最终验收的源码级复查和回归收口。当前正式业务链为：

```text
全局 Agent
-> Global Mission / Epic
-> 精确群聊会话中的群聊主 Agent
-> 一个或多个项目工作项
-> 项目开发 Agent
-> TestAgent 独立验收
-> 最多三轮返工与复验
-> 群聊主 Agent 最终验收
-> 全局 Agent 汇总交付
```

项目会话使用相同责任链，但只允许当前项目主 Agent 调度当前项目的唯一开发 Agent，不创建虚假群聊，也不读取群聊上下文。

## 本轮收口

- 终态交付统一读取正式 `final_delivery_report`，任务卡不再因字段来源不一致丢失最终验收信息。
- 取消状态沿 Global Mission、群聊任务、项目工作项和 TestAgent 执行链传播，已取消工作不会继续进入验收或交付。
- 项目开发 Agent 退出成功仍不能直接完成任务；代码或文件变化必须经过 TestAgent 和主 Agent 双重验收。
- TestAgent 失败会生成精确返工单，最多三轮；仍不通过时进入 `blocked`，不会伪造成功结论。
- 群聊、项目和全局入口的任务体验映射合并到单一 `taskExperience.js`，删除运行时拆分文件，保持原有四个公开导出兼容。
- 容量下降测试改为验证正式压缩门禁：旧工作包必须要求 canonical recompact，不允许本地摘要或字符截断绕过。
- 记忆中心分别统计“快照已成功投递”和“快照完整健康状态”；旧兼容证据产生警告时，不再把真实投递误判为缺失。

## 测试目录

所有 `*-selftest.mjs` 现在必须满足以下任一条件：

1. 登记到领域测试或快速测试。
2. 被兼容 npm 别名引用。
3. 作为参数化 helper 明确登记调用方和原因。

本轮补登 24 个有效自测，并把 2 个需要包装器传参的脚本标记为 helper。目录自测会在出现未分类脚本、重复登记、缺失文件或无原因 helper 时失败。

## 边界

- 本轮证明的是代码契约、隔离范围、状态机和本地回归，不等同于真实第三方 Provider、真实飞书租户或生产账号的在线验收。
- 原始开发输出、TestAgent 报告和返工过程继续进入任务时间线与任务回放；只有主 Agent 正式回复进入聊天正文。
- 任何缺少验收证据、跨 scope、容量门禁失败或模型不可用的修改任务继续 fail closed。
